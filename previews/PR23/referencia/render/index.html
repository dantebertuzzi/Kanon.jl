Rendering

render is pure: no I/O, no clock, no randomness. today is injected. If analyze and check passed, the only possible failure is the resource budget.

Kanon.render — Function
render(bound; budget = Budget()) -> String

Renders data that has already been validated. Pure: no I/O, no clock, no randomness.

source
render(model, data; today = nothing, budget = Budget(), to = PlainText()) -> String

Validates and renders. Throws KanonContractError if the data does not satisfy the contract: there is no rendering without validation, not even as an option (§14).

to selects the output format, as an OutputFormat or by name (:text, :markdown, :typst).

source
Kanon.preview — Function
preview(model, data; today = nothing) -> String

The draft: the document with «markers» where data has not arrived yet. It is not a lenient mode. It is a separate command, its output is always visibly marked, and render still refuses exactly the same data.

What people usually want from a "lenient mode" is to see the text while the data is still being gathered. Serving that here is what lets the engine never relax anywhere else.

source
Kanon.Budget — Type
Budget

Limits that are counted, never wall-clock time (D-010): a time limit would make whether the engine fails non-deterministic. The same input would fail on a loaded machine and pass on an idle one, and the golden suite would become flaky precisely in CI, where slow machines are.

It lives in this file because the first count happens here: the repetitions the rules produce are counted before any text is written.

Output formats

An interpolated value never changes the structure of the document (D-028): the author's prose passes through untouched, and the data is escaped.

Kanon.OutputFormat — Type
OutputFormat

How the text becomes a file. PlainText is the default and touches nothing; the others escape what their format would read as markup.

source

Plain text: nothing is markup, nothing needs escaping.

Markdown. Escapes what CommonMark would read as markup.

Typst. A candidate page backend: Kanon guarantees the content and Typst lays out the page (estado-da-arte.md).

output_format(name) -> OutputFormat

The output format by name. Fails naming the formats that exist: an unknown format would silently write the wrong document, the last thing this engine should do.

source
Kanon.escape_value — Function
escape_value(fmt, text, at_line_start) -> String

Escapes a value that comes from the data. It does not apply to the template's prose: an author who writes **important** in a Markdown template wants bold, and removing it would be editing what they typed, the same mistake a global seam repair would be (D-014).

at_line_start says whether the value is being emitted at the start of a line, which only the renderer knows. Without it, a 12.345 in the middle of a sentence would have to be escaped as if it could open a list, and no value would come out readable.

source

Escapes a value for Markdown.

Tracks line starts because a value can contain line breaks: `"X

Cláusula"` would

put a heading in the document if the # were not escaped there, and escaping it everywhere would fill the text with backslashes without protecting anything.

source

Escapes a value for Typst.

The backslash goes before the digit, not before the dot: 1. x at the start of a line is an explicitly numbered list item, and the way to write it as a paragraph is \1. x, the opposite of Markdown, where the dot takes the backslash. Two markup languages, two rules, which is why escaping is a method per format and not one function.

Three constructs do not open anything visible; they delete, checked against Typst 0.15.1 while compiling the golden output of real template no. 12 (D-062):

  • // starts a comment anywhere on a line: processo 123//2026, vara comes out as processo 123, and the rest of the line disappears without any error;
  • ~ is a non-breaking space: ~200 m² loses its tilde;
  • -? is a soft hyphen, and disappears entirely.

These are the worst kind of defect a format can have: the document compiles and says less than the data did. The slash is escaped only where it forms a comment: next to another slash, or at the edge of the value, where the neighbour is prose the escaper cannot see.

Three more of the same family were found by taking that check to its end, sweeping the whole alphabet against the compiler rather than following a suspicion (D-080). These do not delete, they replace, which is why D-062 missed them:

  • -- is an en dash and --- an em dash: SEI 0001--2026 comes out as SEI 0001–2026;
  • ... is an ellipsis: disse que ... não sabia comes out with ….

A case number that changes a character in a document going to be signed is the same failure as //, made worse by being readable: nobody checks what looks right. The hyphen is escaped by the slash rule, which is the rule for every two-character shortcut: next to another hyphen, or at the edge. The dot is not: an ellipsis needs three, and only a sequence inside the value itself can form one. A single dot at the edge would need the prose to supply the other two, and then the ellipsis is the author's.

Kanon.heading — Function
heading(fmt, level, text) -> String

The label of a block whose style declares layout = :heading. In plain text it is the paragraph the style produced; in a format with headings it becomes a real heading, with the level taken from the depth of the numbering.

source
Kanon.line_breaks — Function
line_breaks(fmt, paragraph) -> String

Line breaks inside a paragraph, which §4.1 preserves and leaves to the format to make hard or not. In plain text the break is already the line the author wrote. In Markdown and Typst a single newline is a space, so a format that decided nothing was in effect joining lines: Nestes termos, and pede deferimento. came out on one line in the .docx, and the signature block became PAULO HENRIQUE LINS OAB/PE 12.345, with no warning, while the plain-text output of the same template was right (D-070, real template no. 15).

A hard break is a backslash at the end of the line, which CommonMark, pandoc's default reader and Typst all read the same way, and which is visible in the file, unlike the two trailing spaces every editor strips. It is added only where the break would otherwise be a space: in runs of consecutive lines where none opens a block construct. A list, table or heading written by the author is their markup and passes through untouched (D-028); a backslash there would break the table and appear literally at the end of the item.

The question is asked of the already escaped text: a value that starts a line with # or 1. arrives here as \# and 1\. and opens nothing, which is what makes the rule safe against the data.

Elision and seam repair

Kanon.repair — Function
repair(chars, seams) -> (text, seams)

Applies the procedure of §5.2: merges adjacent seams, applies R1–R5 once from left to right, and removes lines left empty by a seam.

seams are positions in the text as it came out of elision: seam p lies between chars[p-1] and chars[p]. It also returns the positions after the repair, because those are what the language hook needs; passing the earlier ones would point it at the wrong text (§5.4).

source
Kanon.BlockInstance — Type
BlockInstance

One occurrence of a block in the output. subject is the subject's value (the current element, when the block repeats) and number is the number it took, empty if the block is not numbered.

source
Kanon.Plan — Type
Plan

What the rules decided for this data: the instances in output order, and each block's number for cross-references.

numbers[pos] is empty for a removed or unnumbered block. A repeated block cannot be cross-referenced (K2034, checked without data), so a cross-reference number is never ambiguous.
