Validation

Three steps, three categories of error. Each has what the previous one lacked: parse has no environment, analyze has no data, render has both.

Kanon.analyze — Function
analyze(env, tmpl) -> Analysis

Resolves the template against the environment. Does not mutate the Template and does not throw: it returns the Analysis with the accumulated diagnostics. load_template is what throws.

source
Kanon.Analysis — Type
Analysis

The result of analyze: side tables indexed by NodeId, plus the accumulated diagnostics.

Filled in by phase: paths and formatter come from F2.2; attribute, which holds the canonical name of an is written with a language alias, from D-076; guarded from F2.3; block_index, block_rule and block_foreach from F2.4; numbering from F5.

source
Kanon.ResolvedPath — Type
ResolvedPath

What a path written in the template means, once the environment has been consulted.

nullable is the field the gap theorem relies on: it is true if any segment of the path is optional. Optionality propagates through composite types; otherwise the theorem would hold only at the first level.

source
Kanon.check — Function
check(model, data; today = nothing) -> DiagnosticSet

Does the data satisfy the contract? An empty set means yes.

Deliberately does not throw: check asks the question, and a "no" should come with the whole list of what is missing, not just the first problem.

source
Kanon.bind — Function
bind(model, data; today = nothing) -> Bound

Validates the data against the contract and decodes what passes. Does not throw: it returns the Bound with the accumulated diagnostics and leaves the decision to the caller.

source
Kanon.Bound — Type
Bound

Validated and decoded data, ready to render. values is indexed by the field's position in template.data.fields: file order, which is also the order of the contract and of the errors.

The renderer decodes nothing again: everything that reaches it has been through here.

source
Kanon.contract — Function
contract(model) -> String

The template's data contract, as JSON Schema draft 2020-12 with the x-kanon extension (docs/api-extensao.md §7).

Deterministic: two calls on the same model return the same string, byte for byte.

source

Diagnostics

Errors are user interface here, not an implementation detail. Every diagnostic has a stable code: the test suite asserts on the code, so the wording of a message can improve without breaking a test. The messages themselves are in Portuguese.

Kanon.Diagnostic — Type
Diagnostic

A problem found in a template or in its data. code is stable across versions and is listed in CODE_TITLES.

source
Kanon.DiagnosticSet — Type
DiagnosticSet

An ordered collection of diagnostics. The order is deterministic (file, line, column, code) so the output can be compared with diff and is stable in tests.

source
Kanon.CODE_TITLES — Constant
CODE_TITLES

Registry of every diagnostic code. The title is the short line shown in the problem's header; the full message comes from where the diagnostic is emitted.

Once published, a code never changes meaning (compatibility policy, docs/especificacao.md §13). New codes are additive.

Every code here is emitted somewhere in src/ or lib/, and a test checks that. A code that is never raised misleads: it suggests the engine distinguishes a case it does not, and the first person to build a tool on it finds out the condition never happens. K1213 (unknown marker) and K1304 (unknown operator) were removed for that reason: the first is impossible by construction (the parser does not consult the environment, ast.md §8, and a marker without a style is reported as K2030), and the second was covered by K1302.

K11xx  data plane
K12xx  text plane
K13xx  rules plane
K20xx  references: paths, types and formatters

Kanon.KanonError — Type
KanonError

The root of the engine's exceptions. Each error category in §10.1 has its own, and all of them carry a DiagnosticSet, never a bare message.

source
Kanon.KanonSyntaxError — Type

source
Kanon.KanonReferenceError — Type

Field, formatter or block that does not exist. Detectable without data.

source
Kanon.KanonContractError — Type

Valid template, data that does not satisfy it.

source
Kanon.KanonEnvironmentError — Type

Misconfigured environment: two domains claim the same name, or a layer registered something invalid.

source
Kanon.KanonResourceError — Type

The resource budget was exceeded: the only way rendering can fail (§11, D-010).

It lives here with the other exceptions, not in the renderer, because check can also exceed the budget: rules are evaluated before any text is produced.
