Types and extension

A Kanon type is a set of methods of the core's generic functions. There is no hand-kept dispatch table, no mutable registry, and no eval.

Kanon.kanon_typename — Function
kanon_typename(::Type{T}) -> Symbol

The type's name in the language. Required: it is what makes a Julia type a Kanon type.

source
Kanon.kanon_schema — Function
kanon_schema(::Type{T}) -> Tuple{Vararg{FieldSpec}}

The fields of a composite type, in declaration order. () for a scalar, the default.

source
Kanon.kanon_validate — Function
kanon_validate(v, ctx) -> Nothing | Vector{Diagnostic}

Checks on the value beyond its Julia type. The default checks nothing.

source
Kanon.format — Function
format(v, ::Val{name}, ctx) -> AbstractString

A formatter. Val{:default} is required for every type; the others are optional and listed by kanon_formats.

source

The default is the symbol, which falls back to the currency code when the environment declares none.

source
Kanon.kanon_formats — Function
kanon_formats(::Type{T}) -> Tuple{Vararg{Symbol}}

The named formatters of T, sorted, without :default, which cannot be written in an interpolation: the default is just {price}.

The default implementation inspects the method table of format for signatures Tuple{typeof(format), T′, Val{S}, Any} with T <: T′ and S::Symbol. This is what keeps the promise of docs/api-extensao.md §2.1: a formatter added by plain dispatch, through no facade, exists for template validation and for error messages with no extra registration.

This inspects the method table, not user data: it runs no template code and is deterministic because the result is sorted.

A layer may override this method to document its formatters, or to cover formatters defined generically (format(v::T, ::Val{N}, ctx) where {N}), which inspection cannot enumerate.

source
kanon_formats(T, env) -> Tuple{Vararg{Symbol}}

The formatters of T visible in this environment: the language-independent ones plus those of the active language. This is the list validation uses and error messages show.

kanon_formats(T) on its own still lists everything that exists in the process; that is the protocol, and it knows no environment. The filtering happens here (D-026).

source
Kanon.kanon_format_locale — Function
kanon_format_locale(::Type{T}, ::Val{name}) -> Symbol | Nothing

The language a formatter belongs to, or nothing if it applies in any environment. The default is nothing; a language layer declares its own.

It exists because Julia methods are global and additive: without this declaration, loading Extenso in the process would make {preco:extenso} valid in a neutral environment, and an English report would come out with mil e duzentos reais. Behaviour is still dispatch; what the environment decides is visibility (D-026).

source
Kanon.kanon_attribute — Function
kanon_attribute(v, ::Val{name}) -> Bool

A named predicate, used in the rules plane (when property is rural).

source
Kanon.kanon_attributes — Function
kanon_attributes(::Type{T}) -> Tuple{Vararg{Symbol}}

The attributes of T, sorted, to validate rules without data and for error messages.

present and absent are not listed here: they apply to every field and belong to the engine, not to the type (see UNIVERSAL_ATTRIBUTES).

source
Kanon.UNIVERSAL_ATTRIBUTES — Constant
UNIVERSAL_ATTRIBUTES

Attributes every field has, whatever its type. They belong to the engine: they follow from whether the value is present, and no type implements them.

source
Kanon.kanon_getfield — Function
kanon_getfield(v, ::Val{name})

Reads a field declared by kanon_schema. The default is getproperty(v, name), which works when the field's name in the schema is the Julia property name; a type whose schema does not mirror its struct defines its own methods.

It exists because the schema is the type's interface and the struct is its implementation: without separating them, kanon_schema would become a promise about Julia field names, and renaming an internal field would break existing templates (D-023).

source
Kanon.kanon_decode — Function
kanon_decode(::Type{T}, raw, ctx) -> T

Converts a value from external input (JSON, a spreadsheet, a DataFrame) to the type. It is the only conversion point: there is no implicit coercion anywhere (§3.4).

The default accepts what is already of the type and rejects everything else, failing loudly with the type's name in the message.

source

Money is not decoded from a bare number: the currency would be missing, and guessing it would be the implicit coercion that §3.4 forbids. Accepts a Money, or an amount and a currency.

source
Kanon.kanon_json_schema — Function
kanon_json_schema(::Type{T}) -> Nothing | JSON shape

The JSON shape kanon_decode accepts for T, as JSON Schema: what the contract (contract) publishes under the type's $defs. The default is nothing, and the contract then derives the shape from kanon_schema.

The two descriptions are different things, which is why this function exists (D-079). kanon_schema is the read interface: the fields a template reaches with {pessoa.nome}. Input may require more than that (pessoa needs genero, which decides portador(a) and which no template writes), and a contract derived only from the schema forbade (additionalProperties: false) the key the decoder requires. The JSON data of five real templates, which the engine renders byte for byte, was rejected by their own contract in a JSON Schema validator.

The shape is written with vectors of pairs, which keep their order, so the contract can be compared with diff (D-009):

Kanon.kanon_json_schema(::Type{Pessoa}) = [
    "type" => "object",
    "properties" => [
        "nome"   => ["type" => "string", "title" => "Nome completo"],
        "genero" => ["type" => "string", "enum" => ["f", "m"], "title" => "Gênero"],
    ],
    "required" => ["nome", "genero"],
    "additionalProperties" => false,
]

A reference to another type ("$ref" => "#/$defs/pessoa") is included in the contract along with it.

source
Kanon.kanon_compare — Function
kanon_compare(a::T, b) -> Int

Ordering for the rules plane (price > 0). Returns -1, 0 or 1. The default refuses: comparison requires the type to declare how.

source
Kanon.FieldSpec — Type
FieldSpec

A field of a composite type. optional is what extends the gap theorem into composites: if person.spouse is optional, {seller.spouse.name} is nullable and needs a group (docs/especificacao.md §3.1 and §14).

source

The declarative form

Kanon.@kanon_type — Macro
@kanon_type <name> <JuliaType> begin ... end

Defines a Kanon type through dispatch, from a declarative description.

@kanon_type person Pessoa begin
    schema     = (FieldSpec(:name, :text), FieldSpec(:spouse, :person; optional = true))
    getfield   = (name = :nome, spouse = :conjuge)
    default    = (v, ctx) -> v.nome
    formats    = (formal = (v, ctx) -> uppercase(v.nome),)
    attributes = (minor = v -> v.idade < 18,)
    validate   = (v, ctx) -> nothing
    decode     = (raw, ctx) -> Pessoa(raw)
    compare    = (a, b) -> cmp(a.nome, b)
    locale     = :pt
end

Only default is required. getfield only needs to list the fields whose name in the schema differs from the Julia property name.

aliases do not go here. A name is local to the environment and is registered in the layer's configure!, with register_type!(b, Pessoa; aliases = (pt = :pessoa,)): the split set by D-019 and confirmed by D-025.

locale, when present, declares that this type's named formatters belong to a language and are visible only where it is active (D-026).

Core types

Kanon.Money — Type
Money(amount, currency)

A monetary value: an exact amount and a currency code. The amount is a Rational{Int128}, not a float, because a document that says R$ 1.234,57 cannot depend on binary rounding.

The core prints two decimal places. That is a stated convention, not a property of the currency.

source
Kanon.NumberValue — Type
NumberValue

What counts as a number. Bool is left out on purpose: in Julia it is an Integer, but in Kanon boolean is a separate type; otherwise {flag:fixed2} would be valid.

source

Protocol failures

These are exceptions, not diagnostics: they happen outside a template file, so they have no line or column. check and analyze turn them into diagnostics where there is a position to attribute them to.

Kanon.KanonProtocolError — Type
KanonProtocolError

A failure of the type protocol: the type cannot do what was asked of it.

These are exceptions rather than diagnostics because they happen outside a template file, so they have no line or column. analyze and check catch them and turn them into diagnostics when there is a position to attribute them to.
