Tools

Ingestion

Package extensions, loaded when Tables.jl or JSON3.jl is present. The core depends on neither.

Kanon.rows — Function
rows(table)

The rows of a table, as data. Requires Tables.jl to be loaded: the core does not depend on it, and the extension exists only when it does.

source
Kanon.render_each — Function
render_each(model, table; today, budget) -> Vector{String}

One document per row of the table. Requires Tables.jl to be loaded.

source
Kanon.read_json — Function
read_json(path) -> Dict{String,Any}

Reads data from a JSON file. Requires JSON3.jl to be loaded.

source
Kanon.parse_json — Function
parse_json(text) -> Dict{String,Any}

Like read_json, from a string. Requires JSON3.jl to be loaded.

source

Including fragments

Kanon.Loader — Type
Loader

Where fragments may come from. root is the configured root, and nothing outside it can be loaded: not by absolute path, not by .., not by symbolic link.

Without a root, inclusion is refused: by default no file is read, and whoever wants to include says from where.

source
Kanon.compose — Function
compose(template, loader, keywords) -> Template

Resolves inclusions and returns the composed template: a single Template in which nothing shows there was a fragment, so analysis and rendering do not know about inclusion.

Node identifiers stay unique because every file is parsed with the same counter, which avoids rebuilding the tree to renumber it.

source

Inspection

What an editing tool consumes: the template's structure, already resolved, without reimplementing the analysis (D-029).

Kanon.outline — Function
outline(model) -> Vector{BlockOutline}

The template's skeleton, in file order, which is output order because rules only remove and repeat blocks (D-015).

source
Kanon.BlockOutline — Type
BlockOutline

A block as a tool needs to see it: what it is, what governs it, and what it uses.

rule and foreach are the text of the rule attached to the block (the editor's middle column), and number is the number it takes when nothing is removed.

source
Kanon.FieldUse — Type
FieldUse

A field used by a block: where, with which formatter, and whether it may be absent.

guarded is what the editor's middle column shows in red when missing: a nullable field must sit inside a group, and the editor can say so while the author types.

source
Kanon.format_outline — Function
format_outline(io, model)

The skeleton as aligned text: the block on the left, the rule on the right.

These are the editor's first two columns, in the terminal, and they answer the question the roadmap calls risk 16.2: what comes out of this template, and under which condition?

source

Command line

The CLI logic is in Kanon.main, which takes the streams as arguments and returns the exit code instead of ending the process, so the five exit codes can be tested without a child process.

What that does not test is loading: inside a test suite that has already loaded the layer and JSON3, --domain and reading .json have nothing to load. The flow with a layer is tested through bin/kanon, in a separate process (D-059, D-060).

kanon check    template.kanon [data.json]
kanon render   template.kanon data.json [-o out.md] [--to markdown|typst]
kanon contract template.kanon
kanon preview  template.kanon [data.json]
kanon outline  template.kanon
kanon ask      template.kanon [data] [-o data.json]

With a domain layer: --locale pt --domain KanonLegal. For Portuguese with no domain layer, the language package is loaded the same way: --locale pt --domain Extenso (D-068). ask asks for every missing scalar field, checks each answer with check, and writes the data back in the shape it came in: JSON if the input was JSON or if -o ends in .json (D-061). A number written the way the document prints it is refused, showing the expected form, and an ambiguous one (1.320, in a language where the dot separates thousands) is refused with both readings (D-069).

Exit codes: 0 success, 1 contract, 2 template, 3 usage, 4 resources.
