Templates and environments

The path of a document: an Environment says which layers exist; load_template reads and analyses; check confronts the data; render writes.

Kanon.Environment — Type
Environment(; locale = nothing, domains = [])

The frozen vocabulary of one configuration of layers. Immutable: there is no register_*! on an Environment.

Built in a deterministic, visible order: core, language layer, then each domain in the order of the vector. A name conflict is an error here, with both domains in the message.

Environment() with no arguments is the bare core, the environment of the neutrality test.

source
Kanon.EnvironmentBuilder — Type
EnvironmentBuilder

Construction state of an Environment. It is mutable; the Environment is not. Only the builder has register_*!, and it exists only while the environment is being built, so an environment already in use cannot be mutated.

domain is the layer currently being applied. The constructor keeps it up to date so that a conflict message can name both culprits without the layer having to identify itself.

source
Kanon.load_template — Function
load_template(env, path; root = dirname(path)) -> Model

Like load_string, reading from disk. root is the directory fragments may be included from; it defaults to the template's own directory, and nothing outside it can be loaded (D-005).

source
Kanon.load_string — Function
load_string(env, text; name = "<string>") -> Model

Parses and analyses a template and returns it ready to use. Throws KanonSyntaxError if the text is malformed and KanonReferenceError if a path, type or formatter does not resolve.

A syntax error skips analysis: there is no tree to validate (§10.3).

source
Kanon.Model — Type
Model

A loaded template: the syntax tree, its analysis, and the environment it was analysed in.

Template is the bare syntax tree and knows no environment; Model is the template ready to use. Keeping them apart is what allows the same tree to be analysed in two environments, which the neutrality test does.

Registering names

What a layer registers in the environment is a name, and names are local. Behaviour is methods, and methods are global and additive; the split is in D-025.

Kanon.register_type! — Function
register_type!(b, T::Type; aliases = (,))

Gives the Julia type T a name in the language. The canonical name comes from kanon_typename(T); aliases gives per-language names (aliases = (pt = :dinheiro,)), and only the one for the active language enters the environment.

What the type does (format, validate, decode, compare) does not go through here: it is methods of the generic functions in types.jl, defined in the layer's module (D-019).

source
Kanon.register_type_alias! — Function
register_type_alias!(b, alias, canonical)

Gives an already registered type a name in the active language. This is how dinheiro becomes an alias of money: the core registers its own types and, being neutral, has no aliases to give, and register_type! only accepts aliases from whoever registers the type (D-025).

source
Kanon.register_attribute_alias! — Function
register_attribute_alias!(b, lang, alias, canonical)

Gives the attribute canonical a name in language lang: quando pontos é preciso in a pt template asks the same as when pontos is precise. Applied only when lang is the active language.

It is additive: the canonical name keeps working, and no template changes meaning. An attribute is not a keyword, so D-003 does not apply, just as a type name coexists with its alias.

The language layer registers it, not the layer that defines the attribute: preciso is a Portuguese word, and KanonScience has no language (the glossary form of D-056). A canonical name may have more than one alias, and does when the adjective agrees in gender with the field (a estimativa é precisa, o ponto é preciso). The first one registered is the one the engine writes back in messages.

The alias cannot be a keyword of the language: verdadeiro is already true, and the parser would read it as a keyword before the environment is consulted (D-076).

source
Kanon.register_formatter_alias! — Function
register_formatter_alias!(b, lang, alias, canonical)

Gives the formatter canonical a name in language lang: {nome:maiusculo} in a pt template is {nome:upper}. Applied only when lang is the active language, additive, and registered by the language layer: the same rules as register_attribute_alias!.

Not to be confused with a formatter of a language, such as extenso: that is behaviour, exists through dispatch and is declared by kanon_format_locale (D-026). An alias is only a name, and formats nothing the canonical formatter does not (D-076).

source
Kanon.register_aliases! — Function
register_aliases!(b, lang, forms)

The written forms of the keywords in language lang. Accepts a NamedTuple ((data = "dados", when = "quando")) or any iterable of pairs ([:data => "dados", Symbol("for") => "para"]); the second form exists because for, and and other keywords of the language are reserved in Julia and cannot be NamedTuple keys.

Applied only when lang is the active language.

The corresponding English form stops being a keyword: a file that declares pt writes dados, not data. Mixing them is an error (D-003).

source
Kanon.register_block_style! — Function
register_block_style!(b, name; unit, layout, separator, number, ref)

A domain's block style. unit is the marker unit; two domains registering the same unit is an error here.

source
Kanon.register_inflection! — Function
register_inflection!(b, lang; marks, apply)

The language's inflection marks and the function that applies them. apply receives (word, mark, subject, ctx) and returns the whole word already inflected, which is what allows portador(a) → portadoras without the core knowing how to pluralise (D-013).

source
Kanon.register_repair_hook! — Function
register_repair_hook!(b, lang, hook)

Seam repair hook, called after elision with (text, seams, ctx). Repair is local to the seam, never global (D-014).

source
Kanon.register_list_joiner! — Function
register_list_joiner!(b, lang, f)

How the language joins the elements of a list. f receives the already formatted parts and returns the whole text: ["a","b","c"] ⟶ "a, b e c".

The core joins with ", ", its only typographic convention, stated as such in §3.3 and explicitly replaceable. The replacement is a hook in the environment, not a method on AbstractVector: a method would be global and additive, so loading the layer would change the output of the bare core and break the neutrality that F6 checks (D-025).

source
Kanon.register_currency! — Function
register_currency!(b, code, symbol)

A currency's symbol. money:symbol uses what is declared here; the core embeds no national convention (§3.3).

source
Kanon.register_separators! — Function
register_separators!(b; decimal, group)

The language's decimal and thousands separators. The core prints 0.42 and 1200; the language layer is what makes them 0,42 and 1.200 (§3.3).

source
Kanon.register_date_pattern! — Function

Date pattern for date:numeric. The factory default is ISO.

source
Kanon.configure! — Function
configure!(b::EnvironmentBuilder)

The core's registration: its types and factory defaults. Defined in core_types.jl.

source
Kanon.configure_locale! — Function
configure_locale!(b, ::Val{lang})

Extension point for a language layer. Extenso.jl defines Kanon.configure_locale!(b, ::Val{:pt}); loading the module is enough for the language to exist.

Kanon.typefor — Function

The Julia type registered under name, resolving language aliases. nothing if there is none.

source
Kanon.typenames — Function

Every type name that can be declared in this environment, sorted, for error messages and editor completion. Collection behaviour and its aliases are left out: it exists, but is written through cardinality (D-071).

source
Kanon.stylefor — Function

source
Kanon.hasmark — Function

Is the inflection mark registered? If not, analyze treats the candidate as prose.

source
Kanon.currency_symbol — Function

Currency symbol, or the code itself when the environment declares no symbol (§3.3).

source
Kanon.FormatContext — Type
FormatContext

What a formatter may consult. Deliberately small: the environment and today.

today is injected, never read from the clock, which makes determinism something that can be checked (§2.2). A template that uses today, rendered without it, is a contract error.
